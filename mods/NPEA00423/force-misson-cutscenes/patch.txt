#- name: Force start cutscenes
#- version: 4.0
#- author: robo
#- description: Plays a mission's intro cutscene every time the mission starts, not only the first time.

# Deadlocked records "this mission has been started" as bit 2 (0x4) of the mission's
# status byte in the level save data, at 0xb27ff8 + (level - 1) % 20 * 0x304 + mission * 0xc.
# Two branches read that bit to keep the intro from playing again, and both are nopped
# here, which leaves the game in the state it is in on a first visit to the mission.

# Was 0x408202f0, "bne 0x1d78d8": the intro chooser at 0x1d7550 returns without asking
# for the cutscene when the status bit is already set. nop, so it always asks.
0x1d75e8: 0x60000000

# Was 0x40820010, "bne 0x1d7db0": mission start at 0x1d7ad0 only sets the byte at
# 0x00c763b1, "this is the first start of this mission", while the status bit is still
# clear, and the cutscene camera at 0x12ed24 refuses the intro without it once the bit
# is set. nop, so the byte is always set. The camera clears it again when it takes over,
# so the intro still runs once per mission start, exactly as it does on a first visit.
0x1d7da0: 0x60000000

# Version 3: intros played by a cutscene moby. A mission's intro is either a cutscene id
# or a moby of class 0xF6E, named by its descriptor. The first mission of each planet and
# every mission on Shaar use the moby, and the moby keeps its own record:
#
#   state 0  spawned; 0x412058 arms it (state 1) unless the scene's bit is set in the
#            "scene seen" bitset at 0xb1f58c, in which case it goes straight to 3
#   state 1  armed; its update at 0x412240 plays the scene once 0x7f in its variables
#            is set, again only if the scene is unseen
#   state 2  playing
#   state 3  done, and the chooser skips a moby in state 3 (interface 0x14 at 0x413028)
#
# A seen scene never gets past state 3, so the intro never plays again. Both seen tests
# also pass when byte 0x71 of the moby's variables is set, which is the game's own
# "play every time" switch. The words below replace the chooser's call to the state-3
# test (0x1d7778 to 0x1d779c) with code that sets that switch on the intro moby, puts a
# finished moby back to armed, and clears its "scene queued" byte 0x80 so it queues the
# scene again. Only the moby this mission's descriptor names is touched, and only when
# the mission starts. r31 holds the moby there; r0, r3, r4 and r5 are free, as they
# were across the call these words replace.

# Was 0x60640000, "mr r4,r3". Now "lwz r4,0xac(r31)": the moby's variables.
0x1d7778: 0x809F00AC
# Was 0x63e30000, "mr r3,r31". Now "li r0,1".
0x1d777c: 0x38000001
# Was 0x80a40000, "lwz r5,0(r4)". Now "stb r0,0x71(r4)": play every time.
0x1d7780: 0x98040071
# Was 0xf8410028, "std r2,40(r1)". Now "lbz r5,0x20(r31)": the moby's state.
0x1d7784: 0x88BF0020
# Was 0x7ca903a6, "mtctr r5". Now "cmpwi r5,3".
0x1d7788: 0x2C050003
# Was 0x80440004, "lwz r2,4(r4)". Now "li r3,0": the chooser goes on as for a moby not done.
0x1d778c: 0x38600000
# Was 0x4e9e0421, "bctrl". Now "bne 0x1d779c": a moby not yet done is left as it is.
0x1d7790: 0x4082000C
# Was 0xe8410028, "ld r2,40(r1)". Now "stb r0,0x20(r31)": a done moby is armed again.
0x1d7794: 0x981F0020
# Was 0x2c030000, "cmpwi r3,0". Now "stb r3,0x80(r4)": and queues its scene again.
0x1d7798: 0x98640080
# Was 0x4082013c, "bne 0x1d78d8". nop: the test it made is always passed now.
0x1d779c: 0x60000000

# Version 4: the camera on a cutscene that has already played. Every id cutscene has a
# record in the table at 0xadad10 (0x20 bytes an entry, the record at +0x1c), and the
# record carries four state machines that only run forwards: +0x8c is the camera path
# (0 sets up the start of the pan, 1 waits, 2 runs the pan along the timeline, 3 done),
# and +0x5f, +0x63 and +0x91 step the cutscene's other timed events through their states
# the same way. Starting a cutscene (0x12b754, which calls 0x12b6b0) resets the timeline
# and its flags but none of those four, so the first play after a level load pans and
# every later one finds the camera path already done and holds a static shot. Read on
# the console on Valix mission 2: the two cutscenes that had played sat at 3, 3, 5 and 3,
# the one replaying had its path done, and every cutscene not yet played was at 0.
#
# The words below zero the four at every start, which leaves a record exactly as it is
# before its first play. The room comes from the start itself: its four byte stores to
# +0x104..+0x107 become one word store, and the store of zero to +0x106 that follows the
# reset is redundant. The same is done where a cutscene hands over to the one chained
# after it (0x12c500), which resets the next record inline rather than by the call.
# A cutscene that has never played already holds zeros, so a first play is unchanged.

# 0x12b6b0, the reset every id cutscene start goes through; r4 is the record, r5 is 0.
# Was 0x98a40104, "stb r5,0x104(r4)". Now "stw r5,0x104(r4)": the four flags at once.
0x12b6cc: 0x90A40104
# Was 0x98a40105, "stb r5,0x105(r4)". Now "stw r5,0x8c(r4)": the camera path.
0x12b6d0: 0x90A4008C
# Was 0x98a40106, "stb r5,0x106(r4)". Now "stb r5,0x63(r4)".
0x12b6d8: 0x98A40063
# Was 0x98a40107, "stb r5,0x107(r4)". Now "stb r5,0x91(r4)".
0x12b6e8: 0x98A40091

# 0x12b754, the start itself, just after that call; r23 is the record, r29 is 0.
# Was 0x9bb70106, "stb r29,0x106(r23)", already zero. Now "stb r29,0x5f(r23)".
0x12b888: 0x9BB7005F

# 0x12c500, the chained cutscene's reset; r3 is its record, r20 is 0.
# Was 0x9a830104, "stb r20,0x104(r3)". Now "stw r20,0x104(r3)".
0x12c500: 0x92830104
# Was 0x9a830105, "stb r20,0x105(r3)". Now "stw r20,0x8c(r3)".
0x12c504: 0x9283008C
# Was 0x9a830106, "stb r20,0x106(r3)". Now "stb r20,0x63(r3)".
0x12c50c: 0x9A830063
# Was 0x9a830107, "stb r20,0x107(r3)". Now "stb r20,0x91(r3)".
0x12c51c: 0x9A830091
# Was 0x9a960106, "stb r20,0x106(r22)", already zero; r22 is the same record.
# Now "stb r20,0x5f(r22)".
0x12c588: 0x9A96005F
